## Mandatory Work documentation and audit trail (all tasks)

GitHub Issues/PRs are the single authoritative source of truth for **every** Work task, including partial progress and blocked attempts. No task is complete merely because code or tests pass. These requirements apply on every branch and to all future tasks, unless the user explicitly changes the policy.

1. **Before implementation:** read the current GitHub issue, relevant PRs and task file. Post scope, dependency/base branch, current status, acceptance criteria, and any known blocker to the issue.
2. **As work proceeds:** write consequential design decisions, discoveries, test failures, fixes, deviations, and blockers to the issue/PR rather than relying on ephemeral chat notes.
3. **On completion or stopping:** publish a concise GitHub issue update identifying: what was done; affected files/components and commits/PR links; exact validation commands and test counts/results (including skipped, failing, or unrun checks); CI links/status; security findings; what was **not** verified (especially fixtures versus live behavior); remaining risks/blockers; and the **specific next action**.
4. **Detailed evidence:** create or update `docs/work/issue-<number>-results.md` for each implementation issue, or another clearly linked results document, with reproducible commands, environments, outcomes, troubleshooting and limitations. Link it in the issue and PR. For documentation-only tasks, a complete issue/PR record plus updated documentation is sufficient; do not create empty evidence files.
5. **Handoff:** update `docs/work/task.md` for the next authorized task, clearly distinguishing a proposed next step from permission to execute. Reference the relevant issue and exact base branch. Stop at the current authorized scope.
6. **Honest reporting:** never claim a run, success, deployment, merge, live WhatsApp test, ChatGPT connector acceptance or production readiness without actual evidence. A blocked/incomplete task must still report partial deliverables, failed steps and the exact blocker.

**Required final Work response:** provide the Issue link, PR/commit links, a short validated-results summary, blockers, and exactly what the human should do next. Do not leave the results solely in chat.
